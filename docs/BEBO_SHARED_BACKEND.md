# Bebo shared backend — 2026-10-02

The existing `waseet-ai-api` Cloud Run service now supplies the portable Bebo frontend. No separate backend is created for a recipient.

- Demo: https://waaseet-ai.web.app/bebo/
- Frontend ZIP: https://waaseet-ai.web.app/bebo/BeboAI-Ready.zip
- Local handoff: `dist/BeboAI-Ready.zip`
- Backend base: `https://waseet-ai-api-1041761245251.us-central1.run.app/v1/bebo`

Public routes intentionally support a no-setup guest mascot on arbitrary recipient sites: GET `/status`, POST `/chat`, POST `/speech`. Existing `/v1/ai/*` and other tenant routes retain their authentication. Only routes explicitly marked `beboPublic` are exempt; a prefix or user input cannot bypass tenant authentication.

Chat uses a scoped fast profile inspired by Rafiq: Gemini 3.5 Flash-Lite first, minimal thinking, 128 output tokens, last four history messages truncated to 220 characters, and one sentence limited to 16 words/120 characters. Exact greetings, thanks and self-introductions bypass the model in all five languages. The text inference has a ten-second total deadline, four seconds per attempt and at most three attempts. Existing professional API callers and streaming retain their previous default settings. Bebo does not call the avatar endpoint that would redundantly synthesize audio.

Speech uses the existing TTS service and returns validated WAV directly; input is restricted to 220 characters, five dialects, eight voices, and allowed models. Bebo synthesis has an eight-second attempt deadline, twelve-second total deadline and at most three attempts. It retains a natural speaking rate; no frontend or speech animation acceleration was introduced. Identical concurrent speech requests share one operation. A bounded 32 MB/128-clip memory cache lasts up to 24 hours. A private Cloud Storage cache (BEBO_AUDIO_CACHE_BUCKET=waaseet-ai-bebo-voice-cache) survives instance replacement and lets different instances reuse exact text/dialect/voice/model clips. Objects use daily UTC paths and SHA-256 names; only audio is stored, with no original text or history in object metadata. A two-day lifecycle rule removes live objects (the bucket's default soft-delete recovery policy also applies). Metadata authentication uses the existing Cloud Run service identity, with no new credentials or public bucket access. Cache failure falls back to synthesis. One minimum Cloud Run instance keeps the shared service warm. Public errors omit provider diagnostics and credentials.

Resource controls per Cloud Run instance: 16 requests per client per minute, 120 requests total per minute, and four outstanding provider calls. A route deadline does not release the concurrency slot until its underlying provider promise settles; bounded provider fetches also abort their body reads. These counters are process-local, not a global billing cap across autoscaled instances. All copies share this service and its provider quotas.

`work/package-bebo-cloud.mjs` in the original Bebo workspace copies the original visual assets unchanged and combines the browser-only core and chat code into one classic script. The recipient package has no Node server, env files, or credentials. Opening `index.html` needs internet. The hosted URL requires no extraction or setup. Microphone support depends on browser SpeechRecognition, microphone permission, and a supported secure browsing context; Chrome/Edge with HTTPS is the preferred path.
